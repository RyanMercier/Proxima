## 1. RESOLVED: protocol-flow figure is now script-generated

The original fig9_protocol_flow.png was a hand-drawn export with no source
in the repository, and its drawn labels still showed the pre-correction
mechanism (variance-triggered decision, "no BLS aggregation" fast path).
It has been replaced by `fig_protocol_flow.png`, generated by
`protocol_flow_diagram.py` (manim) at the repository root:

    manim -s --format png -r 1660,1280 --output_file fig_protocol_flow \
        protocol_flow_diagram.py ProtocolFlow

The generated diagram shows the corrected mechanism: Phase 1 messages carry
digest + bloom + conditional 96-byte BLS commitment (64+25+96 B), the
decision node reads ">= 2N/3 matching commitments collected?", and the
fast-path terminal aggregates the Phase 1 commitments into the same
certificate object Phase 2 produces (96 B aggregate + N/8 B bitmap). The
earlier hand re-export instructions are obsolete; the superseded exports
(fig9_protocol_flow.png and the cropped fig9_protocol_flow_proxima.png)
remain in figures/ for the record but are no longer referenced by the
paper.

## 2. Note: "Fig. 9 CSVs" do not exist

The instructions reference regenerating "Fig. 9's bandwidth panel and its
CSVs". The repository's figure pipeline has no CSVs: `visualize.py
figure3()` generates fig3_byzantine_sweep (paper Fig. 2) directly from
an in-process simulation with a fixed seed. The figure was regenerated by
running that script after the Phase 1 payload change; nothing was
hand-edited. Verified under a pinned-clock harness that the code change
leaves success rates, message counts, and tree/HotStuff bandwidth
bit-identical, and raises flat bandwidth by exactly 96 B per matching
validator.

## 3. Note: simulation keeps the unanimity engagement gate

The corrected protocol triggers the fast path at >= 2N/3 matching
commitments. In the benchmark simulation, partial observation is drawn
per-validator (Binomial), so a literal 2N/3 gate would engage in a fraction
of trials at 0-10% Byzantine (e.g. ~23% of trials at 0% Byzantine, N=100,
p_miss=0.37) and would change the reviewed message-panel data of the
Byzantine-sweep figure, which the camera-ready must not do. `blockchain.py`
therefore keeps the conservative unanimity gate (cluster variance ~ 0, now
additionally requiring the 2N/3 signed commitments) for engagement, which
corresponds exactly to the (1-p_miss)^N lower bound reported in the paper;
the certificate itself is the corrected signature-backed object in all
cases. This is documented in code comments; no reviewed number changes.
